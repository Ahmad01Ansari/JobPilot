You are working inside the existing **JobPilot** multi-platform job search and application repository.

This document serves as the comprehensive, production-grade architectural blueprint and phase-wise implementation plan for adding a dedicated platform automation driver for:

```text
Platform: Glassdoor
Primary Domains: https://www.glassdoor.com / https://www.glassdoor.co.in
Target Platform Driver: platforms/glassdoor/
CLI Dispatch: runAiBot.py --platform glassdoor
```

## 1. Executive Scope & Architectural Principles

### 1.1 Core Invariant: Conform, Don't Reinvent
JobPilot already implements a battle-tested multi-tier automation architecture across LinkedIn, Naukri, and Indeed. **Glassdoor must be integrated as an additional platform driver conforming strictly to this shared architecture.**

```text
                            ┌──────────────────────────────────┐
                            │    UI (Desktop PyQt6) / CLI      │
                            └─────────────────┬────────────────┘
                                              │
                                              ▼
                            ┌──────────────────────────────────┐
                            │  Platform Router & CLI Dispatch  │
                            │      (platforms/router.py)       │
                            └─────────────────┬────────────────┘
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
         Existing Platforms                                   Glassdoor Platform Driver
  (LinkedIn, Naukri, Indeed, Foundit)                         (platforms/glassdoor/)
                                                                        │
                    ┌───────────────────────────────────────────────────┘
                    ▼
     Shared Intelligence & Core Services (DO NOT DUPLICATE)
     ├── QualificationEngine   (modules/qualification_engine.py)
     ├── QnA Engine            (modules/qna_engine.py - 3-tier catalog/resume/LLM)
     ├── Resume Manager        (app/services/resume_service.py)
     ├── ApplicationTracker    (modules/tracker.py - SQLite DB)
     ├── AutomationBridge      (app/services/automation_bridge.py - Qt/Signal emitter)
     ├── Captcha Resolver      (CaptchaResolver.md - Cloudflare, reCAPTCHA, HITL)
     └── ConfigLoader          (modules/config_loader.py - profile.json + DB)
```

### 1.2 Mandatory Architectural Rules
1. **Never Duplicate Shared Business Logic**: Do NOT create a custom `GlassdoorQnAEngine`, `GlassdoorResumeManager`, or `GlassdoorQualificationEngine`. Use the existing modules.
2. **Never Fake Submission**: An application must NEVER be marked as `SUBMITTED` merely because the "Submit" or "Apply" button was clicked. Positive confirmation (modal transition, success banner, "Applied" badge) is required.
3. **No Brittle Infinite Loops**: Every search pagination, form transition, and modal wait must be bounded by explicit timeouts and check the cooperative `stop_check()` signal on every iteration.
4. **Resilient Error Isolation**: A malformed job card or unsupported questionnaire field on a single job must NEVER crash the entire Glassdoor run. Isolate errors at the per-job boundary.
5. **Zero Hallucination Policy**: Form answers generated by AI must originate strictly from verified candidate profile data, resume facts, or explicit screening rules.

## 3. Human Behavior Emulation & Anti-Bot Defense

Glassdoor utilizes sophisticated bot detection (Cloudflare WAF, Turnstile, PerimeterX/Human Security, and heuristic browser profiling). The driver must emulate authentic human behavior at every stage:

### 3.1 Dynamic Humanized Delays & Timing Jitter
- **Gaussian Jitter**: Do not use hardcoded `time.sleep(N)`. All inter-action delays must sample from a random distribution bounded by configurable parameters (`human_delay_min` = 1.5s, `human_delay_max` = 4.2s).
- **Dwell Time Heuristics**: Before qualifying or clicking Apply, pause for a dynamic "reading period" calculated based on the length of the job description (e.g., $1.5\text{s} + \min(\text{len}(JD) / 400, 3.5\text{s})$) to simulate a user scanning the requirements.
- **Micro-Pauses Before Action**: Prior to clicking buttons or submitting forms, introduce a 600ms – 1400ms micro-pause to simulate visual target acquisition.

### 3.2 Natural Micro-Scrolling & Viewport Inspection
- Use smooth JavaScript-driven micro-scrolling (`window.scrollBy({top: delta, behavior: 'smooth'})`) rather than instant DOM jumps.
- When reviewing long descriptions or multi-page forms, scroll incrementally down the container, pause momentarily, and scroll back up slightly (simulating a candidate checking details).

### 3.3 Authentic Keyboard Simulation
- Input text character-by-character with realistic typing cadences (50ms to 180ms delay per keystroke) rather than dumping strings instantly with `element.send_keys(val)`.
- Occasionally simulate small pauses between words (200ms – 400ms) for longer text fields and cover letters.

### 3.4 Stealth Profile & CDP Hardening
- Dedicated persistent Chrome profile: `~/.jobpilot-glassdoor-profile`.
- Built on `undetected-chromedriver` with automated CDP patches:
  - Mask `navigator.webdriver = true`.
  - Provide valid `navigator.plugins`, `navigator.languages = ['en-US', 'en']`.
  - Enable WebGL vendor and renderer spoofing.
  - Disable automation extension flags (`--disable-blink-features=AutomationControlled`).

## 4. CAPTCHA, Turnstile & Security Challenge Architecture

Aligned with `CaptchaResolver.md`, Glassdoor challenges must be handled across three distinct tiers without violating anti-bypass safety rules:

```text
                          [ Glassdoor Page / Form Load ]
                                        │
                         ┌──────────────┴──────────────┐
                         ▼                             ▼
            [ Real Challenge Visible? ]   [ Background Invisible Telemetry ]
                         │                             │
                         │ YES                         │ NO (Ignore Telemetry)
                         ▼                             ▼
            [ Classify Challenge Type ]      [ Proceed with Flow Directly ]
                         │
      ┌──────────────────┼─────────────────────────┐
      ▼                  ▼                         ▼
[ Cloudflare ]    [ reCAPTCHA v2 / ]        [ Glassdoor Sign-In ]
[ Turnstile  ]    [ Enterprise Bframe ]     [ Overlay Wall      ]
      │                  │                         │
      ▼                  ▼                         ▼
[ Auto/Wait ]     [ Buster Audio / ]        [ Dismiss Overlay / ]
                  [ Manual Puzzle  ]        [ Auth Re-Inject    ]
      │                  │                         │
      └──────────────────┼─────────────────────────┘
                         ▼
          [ Cooperative HITL Intervention ]
        - Emit CAPTCHA_DETECTED event
        - Display Desktop UI Intervention Banner
        - Pause worker, poll for resolution (max 60s)
        - Stop immediately if stop_check() fires
```

### 4.1 Challenge Classification
| Challenge Type | DOM Fingerprint / Indicator | Strategy |
|---|---|---|
| **Cloudflare Turnstile** | `iframe[src*='challenges.cloudflare.com']`, `#challenge-stage` | Pause automation, allow token auto-resolution or prompt user via HITL banner. |
| **Google reCAPTCHA (v2/Ent)** | Visible `iframe[src*='bframe']` ($\ge 250\times250$px) | Buster audio extension auto-solve or cooperative manual intervention. |
| **Invisible Telemetry** | Hidden `<textarea id="g-recaptcha-response">`, `.grecaptcha-badge` | **IGNORE completely**; do NOT trigger false-positive manual pauses. |
| **Glassdoor Sign-In Wall** | `div[id*='HdrModal']`, `div[class*='ContentWall']`, `button[aria-label='Close']` | Dismiss overlay via close button or authenticate session. |

### 4.2 Cooperative Human-in-the-Loop (HITL) Protocol
1. When a visible, blocking challenge is confirmed:
2. The driver emits `AutomationInterventionEvent(type=CAPTCHA_DETECTED, platform='glassdoor')` via `AutomationBridge`.
3. The Desktop UI highlights the application window and opens the non-intrusive `CaptchaInterventionDialog`.
4. The worker enters a cooperative loop (polling `is_captcha_solved()` every 1.5s for up to 60s).
5. If resolved or token generated, the worker resumes immediately. If time expires or user cancels, mark `MANUAL_REQUIRED` and gracefully move to next job.

- `daily_limit` / `switch_number`: positive integers (default 25).
- Candidate CTC, desired salary, and notice period must be valid.

## 6. Glassdoor Application Flow Taxonomy

Glassdoor features three primary application dispatch pathways:

```text
                               [ Discovered Glassdoor Job Card ]
                                               │
                                 ┌─────────────┴─────────────┐
                                 ▼                           ▼
                     [ Glassdoor "Easy Apply" ]    [ "Apply on Company Site" ]
                                 │                           │
                   ┌─────────────┴─────────────┐             ▼
                   ▼                           ▼    [ EXTERNAL FLOW ]
         [ Native Glassdoor Modal ]    [ Indeed Smart Apply ]
                   │                     (Cross-Platform)    - Capture redirect URL
                   ▼                           │             - Clean tracking params
         [ Multi-Step Form ]                   ▼             - Record EXTERNAL in DB
         1. Contact Info (Profile)     [ Indeed Smart Apply ]- Close extra tab
         2. Resume Selection           [ Window & Form Flow ]- Refocus Glassdoor
         3. Screener Questions (QnA)           │
         4. Work Auth & Demographics           ▼
         5. Review & Submit                    │
                   │                           │
                   └─────────────┬─────────────┘
                                 ▼
                     [ SUBMITTED CONFIRMATION ]
```

1. **Native Glassdoor Easy Apply**: Multi-step modal overlay on `glassdoor.com`. Traversed by `GlassdoorForm`.
2. **Indeed Smart Apply Integration**: Glassdoor and Indeed (both owned by Recruit Holdings) share job networks. Often an "Easy Apply" job opens an Indeed Smart Apply modal or tab (`apply.indeed.com`). The driver seamlessly delegates to or reuses the `IndeedForm` handler.
3. **External Company Site**: Clicks open an external employer portal (Workday, Greenhouse, Lever, etc.). The driver captures the clean destination URL, logs `EXTERNAL` in `ApplicationTracker`, closes the popup tab, and refocuses Glassdoor SRP.

### Phase O: Controlled Live Smoke Test & Acceptance Gate
- **Goal**: Validate live platform behavior in a safe, supervised environment.
- **Key Real-World Discoveries & Resolution Architecture**:
  1. **"Create job alert" Modal Interception**:
     - Glassdoor frequently displays a persistent `JobAlertModal_modalWrapper__UEN7p` modal over the SRP.
     - The close button utilizes `data-test="job-alert-modal-close"` and `aria-label="Cancel"`.
     - Standard `aria-label="Close"` selectors fail to dismiss it.
     - Solution: Targeted CSS/XPath selectors and DOM unlinking in `dismiss_overlays()` called before search, card selection, and form actions.

     - Glassdoor SRP detail pane renders Easy Apply with `data-test="easyApply"`, not legacy `data-easy-apply="true"`.
